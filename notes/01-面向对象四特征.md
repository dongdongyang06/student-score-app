# 面向对象四个特征



## 一句话

封装是藏细节，继承是少写重复，多态是同一动作不同表现，抽象是只留必要的接口。



## 1. 封装



**我的代码**：`Student` 里的 `private double score`，外部只能用 `getScore()` / `setScore()`，不能直接改。



**亲历**：我把 `score` 从公开改成 private 的那一刻，编译器立刻报出 5 处错误——`save()`、`update()`、`sortedByScoreDesc()`、`doUpdate()`、`printTable()` 都在直接访问 `s.score`。如果字段一直公开，我永远不知道有谁在偷偷改它。



**还留着的坑**：`StudentManager.all()` 直接 `return students`，外部一句 `mgr.all().clear()` 就能清空整个名单。改法：`return new ArrayList<>(students);`



**面试问**：封装的意义？

答：改内部实现时（List 换成数据库、内存换成 Redis），调用方一行都不用改。



## 2. 继承



**我的代码**：`static class Student extends Person`，构造里 `super(id, name)` 把 id、name 交给父类，Student 自己只多写一个 score。



**为什么这么写**：以后加研究生，id、name 的存储逻辑不用再写一遍。



**面试问**：为什么说组合优于继承？

答：继承是编译期绑死，父类一改子类跟着坏；组合只依赖接口，换实现不动调用方。我这里的 Person 只有 id、name 两个纯数据字段，属于继承的合理用法。



## 3. 多态



**我的代码**：`printTable` 里写的是 `s.getRole()`，它只知道"这是一个 Person，能报出身份"。将来加一个：



&#x20;   static class GraduateStudent extends Student {

&#x20;       @Override String getRole() { return "研究生"; }

&#x20;   }



表格代码一行都不用改，就会打印"研究生"。



**面试问**：多态底层怎么实现？

答：虚方法表。运行时按对象的**实际类型**找方法，不是按引用类型——所以 `Person p = new Student(...)` 调 `getRole()` 走的是 Student 的实现。



## 4. 抽象



**我的代码**：`abstract class Person` 不能被 new；`abstract String getRole()` 只有声明没有实现。



**抽象的价值**：`main` 只调 `mgr.add()` / `mgr.search()`，完全不知道数据存在 List 还是文件里——把"怎么存"抽掉，只留"能做什么"。



**面试问**：抽象类和接口怎么选？

答：有共享状态和构造逻辑（比如 id、name 的初始化）用抽象类；只约定行为、可能要多实现用接口。



## 一句话总结

四个特征不是四个名词，是四件工程上的事：藏细节、少写重复、换实现不改调用、先想接口再想实现。
